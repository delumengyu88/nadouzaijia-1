# 那豆在架小程序

原生微信小程序，目录就是本文件夹。默认使用混合模式：检索、结果列表、报告及其导出来自真实 API，其他功能为本地模拟。API 地址保持空占位，需要在本机配置后才能检索。

## 导入微信开发者工具

1. 安装微信开发者工具（稳定版）。
2. 选择「导入项目」。
3. 目录选中本仓库里的 `miniprogram` 文件夹，不要选仓库根目录。
4. AppID 保持 `touristappid`，使用测试号或游客模式。不要把正式 AppID 写回仓库。
5. 本地设置里关闭「校验合法域名」。连自己的后端时也要先关掉，否则请求会被拦截。
6. 编译。入口是首页。第一次打开会看到开屏，右上角「跳过」后进入首页。开屏、公告和查询完成都盖在完整首页上，底部标签在遮罩下面。

底部标签只有三项：首页、会员中心、个人中心。

## 本地数据与后端

开关在 `config.js`：

- `mode: 'hybrid'`（默认）：逐项调用 `GET /api/v1/programs/search?name=`，本地管理查询进度；网络失败显示失败项，可单项或全部重试，绝不回退为模拟命中。报告等待异步结果，支持重试。
- `mode: 'mock'`：全部模拟，不访问网络。
- `mode: 'live'`：使用 HTTP adapter；尚未接入的非检索接口不可用，不用于本次内测。
- `trialMode: true`：所有支付入口只弹出体验版提示，不创建订单或模拟发放。设为 `false` 后移除提示及测试身份切换入口。它不会自动把其他模拟接口变为真实接口。
- `apiBase: ''`：仅在本机填写服务根地址，仓库保持空占位。
- `testUserIds`：免费/会员测试身份对应的 `X-User-Id`，在 mock 个人中心切换。需要与后端已有测试用户 ID 一致；切换模拟会员不会给后端发放权益，真实报告权限完全由后端决定。没有微信登录。

查询任务在本次小程序进程中按测试身份隔离，关闭进程后需重新查询。查询记录页仍为模拟样例，样例 ID 不会发起伪造后端查询。首页固定示例仍为模拟；从检索进入的报告、平台、类别、日期和锁定统计全部来自后端。导出时重新请求以校验权限，只导出允许下载的真实记录。

当前后端截图签名仍是本地 `signed://derived/` 占位协议，无法当作小程序图片加载；真实报告保留记录字段，截图显示不可用，不借用模拟图。导出沿用本地 xlsx 格式，截图列为“暂无截图”；未接入正式截图存储或签名服务。

## 演示账号

个人中心底部「切换账号」：

| 账号 | 能看到什么 |
| --- | --- |
| 未登录 | 首页游客提示。开始查询会先要求登录。 |
| 免费用户 | 报告里的记录是毛玻璃，只显示条数、日期和「涉及 N 个平台」。 |
| 会员 | 已开通 VIP，同时有一段普通会员，两段同时计时。取证申请、订单和查询记录都有样例。 |

邀请码在免费用户下兑换。每个账号只能绑定一次。码为 8 位大写字母或数字，去掉了易混字符。

| 输入 | 结果 |
| --- | --- |
| `A8K3N2P7` | 成功，发放普通会员 30 天 |
| `B7C4D6E8` | 无效 |
| `C9D5E7F2` | 已过期 |
| `D4E6F8G3` | 已被使用 |
| 已绑定后再填 | 不能再填 |

若该账号已经是 VIP，成功页会写明与 VIP 同时计时。连续输错 5 次后锁定 1 小时。

支付没有商户号。仅在 `mock` 且关闭 `trialMode` 的开发检查中，支付页用结果按钮代替微信支付弹窗。支付失败后主按钮是「查看订单状态」。确认未支付后才出现「重新支付」，订单号不变。

建议演示顺序：首页输入下面四行，开始查询，确认后看结果。

```
星河旧梦
长街烟火
雾港来信
南岭追光
```

`南岭追光` 第一次会失败，可单条重试。会员账号的取证列表里有失败并已全额退款的一单。

## 还缺的外部条件

- 正式小程序 AppID（现在是游客号）
- ICP 备案通过后才能上线
- 一台自有服务器，以及已备案的 https 域名
- 微信支付商户号和虚拟支付权限
- 只读数据账号与授权
- 画面校准数据

这些都不要写进仓库。
